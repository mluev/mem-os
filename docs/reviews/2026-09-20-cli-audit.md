# CLI audit and repair — 20 September 2026

## Assessment

The standalone client has a sound boundary: HTTP and SSH on the client, server
dependencies on the host. Its original 39 tests passed, but several advertised
behaviors failed at configuration, argument, and process boundaries. Route
coverage alone did not establish that all commands and options worked.

The findings below are fixed in the working tree. Existing unrelated changes
were preserved. No release or deployment was performed.

## Fixed findings

| Priority | Finding | Repair |
| --- | --- | --- |
| P1 | Reinstall reset custom ports and could discard the saved device key. | Omitted options preserve the named connection. Conflicting remote settings are rejected; remote metadata supplies the actual deployment port. |
| P1 | Claude transcript import accepted but ignored `--limit`. | Shared operation metadata forwards a positive limit for preview and applied imports. |
| P2 | Failed `server doctor` discarded the useful check report. | Retain sanitized checks in the error message and additive `error.details`, with a failing exit status. |
| P2 | Invalid configuration, malformed responses, and SSH timeouts escaped as tracebacks. | Validate saved and agent settings, HTTP/SSH envelopes, and consumed job/profile shapes. Tunnel/download timeouts return exit 8 and preserve existing output files. |
| P2 | Global option parsing consumed literal arguments after `--`; null field overrides disappeared. | Respect the option terminator, retain explicit nulls, and reject nonfinite timeout/wait values. |
| P2 | Public API requests and setup did not reopen saved tunnels. | Use the same connection path as authenticated commands and hooks, without sending API keys on public requests. |
| P2 | Existing options and an optional API body were missing from discovery. | Expose `doctor --load-model`, `drain-index --retry-now`, `backup create --kind`, and the optional `admin reextract` body fields. |
| P2 | Error responses were fully buffered before truncation; pagination excluded its first request from the wait budget. | Stop reading errors at 8 KiB and start pagination's budget before the initial API request. |

Argument construction, API execution, and rendering now have separate modules.
Server option definitions drive both parsing and SSH forwarding. Snapshot
transformations check their expected source structure and finish generating
all content before writing, preventing partial updates when sources drift.

## Verification

- 157 CLI tests pass on each of Python 3.11, 3.12, and 3.13.
- Independent contract tests exercise all 67 API operations, including all
  declared path/query/body arguments and actual HTTP serialization.
- 170 related server, export, and adapter tests pass, plus 49 subtests.
- Source distribution and wheel build successfully. Clean wheel smoke tests
  pass on all three Python versions without server packages or models installed.
- Lint, formatting, and generated-asset synchronization checks pass.
- One pre-existing Starlette/HTTPX deprecation warning remains in the related tests.

## Initial verification limit

Live install, upgrade, and restore have **not** been verified in this audit.
GitHub returned 404 for `memos-cli.yml` on the default branch, and no disposable
SSH target was supplied. Unit tests with simulated subprocesses cannot prove
Docker, database restore, or model readiness behavior on a real host.

The disposable-host smoke script now additionally checks reinstallation without
repeating ports, public-command tunnel reopening, import limits, and rollback
after an image actually becomes unhealthy. Run the workflow's `remote_smoke`
job against this revision once it is published, or run the script against an
explicitly disposable Linux SSH host. Live verification remains a release gate;
the passing local checks do not establish production readiness.

## Follow-up live verification

The [disposable-host run](https://github.com/mluev/mem-os/actions/runs/35509340199)
passed against revision `e59801d`: fresh cache permissions, SSH installation,
tunnel reopening, persistence, reinstallation, upgrade, missing-image failure,
unhealthy-image rollback, import limits, backup verification/download, restore,
and export. Restoring retained the original memory and removed the memory added
after the backup. The run used real Postgres, Qdrant, Docker and the embedding
model on an isolated GitHub runner; no production host was used.

Live checks found and fixed two defects that simulated subprocess tests missed:
Docker reset ownership of an empty model cache, and `pg_restore` lacked an
explicit database target. Restoration is now transactional; interrupted setup
can be retried without replacing saved credentials. There are now 158 CLI tests
passing on Python 3.11, 3.12 and 3.13. The integrated local backend passes 818
tests and 55 subtests with 81.04% coverage (two Qdrant-only tests run separately).
