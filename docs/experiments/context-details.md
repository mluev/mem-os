# Jev: точность контекста и сохранение деталей

Дата: 20 сентября 2026. Модель: `jev-1.13.0`. Выполнены восемь серий
сравнений; сохранены и удачные, и неудачные варианты. Это результаты на
синтетических данных, не оценка качества на реальных пользователях.

## Что изменено

- Добавлен режим поиска `contribution`: Jev определяет, содержит ли кандидат
  хотя бы одну нужную деталь. Частичный ответ на широкий вопрос больше не обязан
  преодолевать порог, рассчитанный по средней оценке полноты ответа.
- Добавлена совместная сборка контекста из фактов и исходных пользовательских
  сообщений. Она включается настройкой `MEMKIT_SEMANTIC_CONTEXT=select|compact`
  и только при явном `include_raw=true` в запросе поиска.
- В режиме `compact` отдельный блок Jev удаляет смысловые повторы из выдачи.
  История и сами воспоминания не изменяются. Исключения, причины и противоречия
  должны сохраняться; модельные решения остаются вероятностными.
- Факты, цитаты и дополнительные `include_sources` используют общий бюджет
  контента. Для каждого элемента учитываются текст и шесть токенов обрамления.
- Перед отправкой исходного сообщения модели его текст, роль и область доступа
  перечитываются из PostgreSQL. Текст из потенциально устаревшего Qdrant не
  используется как источник. Проверены фильтры, недоступные области, сообщения
  ассистента, отказ провайдера и ограничение бюджета.

В локальном `.env` выбраны `semantic_retrieval=contribution` и
`semantic_context=compact`. Сервис не перезапускался и не развёртывался.
Распространяемые настройки по умолчанию остаются выключенными. Обычный запрос
без `include_raw` не активирует работу с исходными сообщениями.

## Данные и метод

Новый корпус: 16 вымышленных сценариев, 48 запросов, 112 текстов и 96 проверок
покрытия источника. Русский, английский, узбекский и смешанный язык. В каждом
сценарии есть краткие повторяющиеся факты, исходные фрагменты с причинами и
исключениями, похожий посторонний проект и вопрос без ответа в памяти.

Восемь семейств использованы для настройки; восемь отложены до фиксации
вопросов и порогов. Запросы и перефразировки внутри семейства зависимы.
Разметка авторская, без независимой человеческой проверки. Разметка отдельных
деталей не равнозначна разметке строгой логической эквивалентности утверждений.

Основное сравнение проводилось при одинаковом бюджете **160 токенов**. Для
поиска использованы настоящие BGE-M3 и PostgreSQL, а Qdrant — в локальном режиме
точного поиска. Рабочая база сервиса не открывалась. ANN на сервере, нагрузка
и большие реальные истории этим экспериментом не проверяются.

Сначала цитаты представлялись отдельными экспериментальными записями для
сравнения способов отбора. Затем выполнена отдельная проверка настоящего пути:
факты в `memories`, сообщения в `messages`, два соответствующих индекса.

## Основные результаты

На отложенных 24 запросах нужно сохранить 40 деталей суммарно. Восемь запросов
не имеют ответа. Число лишних фрагментов — сумма по всем запросам, не процент.

| Представление и отбор | Нужные детали / 40 | Лишние фрагменты | Правильные пустые ответы / 8 |
| --- | ---: | ---: | ---: |
| Только краткие факты, текущий поиск | 8 | 109 | 0 |
| Факты + фрагменты, без Jev | 27 | 79 | 0 |
| Факты + фрагменты, прежний Score-фильтр Jev | 30 | 2 | 8 |
| Факты + фрагменты, Contribution | 36 | 1 | 8 |
| Contribution + удаление повторов | 36 | 1 | 8 |

Таким образом, большая часть прироста полноты получена **доступностью исходных
деталей**. Jev улучшил точность отбора. Сжатие не добавило деталей на этой
отложенной выборке, хотя уменьшило число повторных фрагментов в выдаче.

На настоящем пути с двумя коллекциями результат несколько иной — это отдельная
интеграционная диагностика на уже открытых сценариях:

| Вариант | Нужные детали / 40 | Лишние фрагменты | Правильные пустые ответы / 8 |
| --- | ---: | ---: | ---: |
| Факты + сообщения, без Jev | 34 | 70 | 0 |
| То же + Contribution | 36 | 0 | 8 |
| То же + удаление повторов | 37 | 0 | 8 |

Исходные сообщения возвращаются как цитаты с датами и идентификаторами, а не
как подтверждённые актуальные факты. Более позднее сообщение само по себе не
доказывает, что оно заменяет раннее. Автоматического разрешения противоречий нет.

## Проверка более простых альтернатив

Повторная обработка того же зафиксированного набора кандидатов без новых вызовов:

| Бюджет | Приоритет источников без Jev: детали / лишние | Contribution: детали / лишние | Contribution + приоритет источников: детали / лишние |
| --- | ---: | ---: | ---: |
| 80 | 30 / 35 | 27 / 0 | 32 / 0 |
| 160 | 40 / 74 | 36 / 0 | 39 / 0 |
| 320 | 40 / 195 | 39 / 0 | 39 / 0 |

Это **компромисс полноты и точности**, а не доказательство, что Jev всегда лучше.
Приоритет источников без модели сохранил больше деталей, но дал много шума.
Приоритет источников после Jev перспективен, однако выбран уже после открытия
проверочной выборки; в рабочую политику его не переносили без нового испытания.

Метрика повторов в подробных артефактах считает элементы, чьи размеченные детали
уже встречались раньше в порядке выдачи. Она зависит от порядка элементов; для
сравнения полноты используется независимое от порядка объединение деталей.

## Что не принято

1. **Прежний Score-порог для широких вопросов.** На настроечных примерах полезные
   частичные ответы получали 1.87–1.98 и отбрасывались порогом 2.0. Contribution
   проверяет наличие полезного вклада напрямую. Старый режим сохранён для сравнения.
2. **Удаление повторов с порогом 0.95.** Не изменило полноту, но добавило запросы.
   Порог 0.70 выбран на настроечных данных и затем проверен без изменения.
3. **Блок контроля потерь как автоматический дополнительный проход извлечения.**
   На 96 простых пробах найдено 48/48 пропущенных деталей, но были два ложных
   сигнала при полном покрытии. Отрицательные примеры содержат точную копию
   источника, поэтому простая проверка вхождения решает этот набор без модели.
   Это недостаточное основание для автоматических повторных извлечений.
4. **Расширение кандидатов для удаления дублей.** На 96 парах широкий отбор
   вернул часть пропущенных совпадений, но стабильного преимущества не установлено.
   Кроме того, некоторые «перефразировки» корпуса различаются модальностью или
   словом «обычно»: их нельзя считать строгими дублями только по общей теме.
   Порог записи и правила объединения памяти не менялись. Этот эксперимент
   сохранён как ограниченная диагностика, не как доказательство слабости модели.
5. **Замена индексов или генеративного экстрактора.** Результаты подтверждают пользу
   Jev на этапе выбора, но не дают основания заменять хранение, поиск кандидатов
   или генерацию текста воспоминаний.

Предыдущий независимый от нового корпуса регрессионный набор также пройден:
Contribution сохранил 21/21 полезный фрагмент, вернул пустой ответ на 12/12
неответимых запросов и не вернул нерелевантных фрагментов.

## Задержка, цена и ограничения

В интеграционной диагностике поиск с Contribution занимал около **1.01 секунды
по медиане**. Сумма задержек провайдера для режима с удалением повторов:
медиана **1.04 с**, 95-й процентиль **3.30 с**. Последний показатель не включает
базы и локальные вычисления. Часть повторных вызовов бралась из точного кеша,
поэтому измеренную wall-time режима compact нельзя сравнивать напрямую с select.

В восьми сериях зафиксированы 969 новых вызовов с подробным usage, 2,370,531
входной токен и ноль ошибок провайдера. При опубликованной цене
[$0.042 за миллион входных токенов](https://docs.typesafe.ai/models) это оценочно
**$0.0996**. Ещё 24 вызова старого регрессионного runner не сохранили подробный
usage и в эту сумму не включены. Это расчёт по usage, не сверка счёта провайдера.

Настроены пределы кандидатов и числа шагов. Пять секунд проверяются между
вызовами; выполняющийся запрос не прерывается этим ограничением. Сетевые
операции имеют таймаут три секунды, но это не строгий предел всей длительности запроса.
При отказе провайдера сохраняется исходная подборка в пределах бюджета.
Очень длинные неразбиваемые сообщения и фрагменты после восьмого не рассматриваются.
Не измерены крупные истории, реальные пользовательские запросы и пропуски ANN.

## Проверки и воспроизводимость

Полный набор backend-тестов: **805 passed, 2 skipped, 49 subtests passed**.
Последующие проверки ограничения времени и сжатых архивов прошли отдельно.
Проверены lint, согласованность документационных блоков и целостность архивов.

Код запусков: `eval/context_experiments.py`, `eval/context_runtime.py`,
`eval/context_ablation.py`, `eval/context_relations.py`.
Корпус: `eval/corpora/context-details-v1.json`. Все опубликованные подробные
артефакты синтетические; они сжаты gzip без потери данных. Проверка архива
проверяет хеш исходного JSON после распаковки. Источник, вопросы, ответы,
пороговые значения и идентичность кода сохранены.

Ссылки на восемь серий приведены в [реестре экспериментов](README.md#context-detail-experiments).

## Проверка при подготовке PR

Compaction теперь считает покрытием только те предыдущие фрагменты, которые
помещаются в оставшийся бюджет и лимит ответа. Иначе длинная цитата могла
вытеснить короткий полезный факт, а затем сама не попасть в ответ. Отдельные
регрессионные тесты воспроизводят этот случай и ограничение числа результатов.

Повторная интеграционная диагностика на уже открытом корпусе сохранила
**37/40 деталей, 0 лишних фрагментов и 8/8 правильных пустых ответов**. Все
семантические ответы взяты из кеша точных запросов; новых вызовов и расходов
не было. Это проверка сборки контекста, а не независимое подтверждение качества
модели или её задержки. [Архив проверки](runs/20260920T113215964755Z-context-budget-aware-compaction-regression-27300a4e/report.md).
