# 01 — Архитектура

## Компоненты

```
       агенты (чат, кодер, ресерч)
                  │  HTTP
                  ▼
       ┌────────────────────┐
       │   Memory Service   │  FastAPI
       │                    │
       │  ingest  search    │
       │  admin   consolidate│
       └─┬────────┬───────┬─┘
         │        │       │
         ▼        ▼       ▼
     SQLite    Qdrant   Claude API
   (правда)   (индекс)   (судья)
                 ▲
                 │
            BGE-M3 (локально, MPS)
```

## Стек

- Python 3.11+, FastAPI, uvicorn
- Qdrant в Docker (`qdrant/qdrant`, порт 6333)
- `sentence-transformers` + `BAAI/bge-m3`, device `mps`
- `anthropic` SDK, модель `claude-haiku-4-5`
- SQLite через `sqlite3` или SQLModel
- Очередь фоновых задач: на старте — `asyncio.Queue` в процессе. Позже, если
  понадобится переживать рестарт, — таблица `jobs` в SQLite с воркером.
  Redis/Celery не нужен, у тебя один пользователь.

## Путь записи

```
сообщение приходит
      ↓
[1] сразу пишем в SQLite (messages)  ──→ ответ агенту, не ждём
      ↓
[2] проверяем gate: пора звать судью?
      ↓ нет → выходим
      ↓ да
[3] берём окно последних сообщений
      ↓
[4] эмбеддим окно → ищем в Qdrant 8 похожих фактов
      ↓
[5] Haiku: (окно + кандидаты) → список операций
      ↓
[6] применяем операции: ADD / UPDATE / DELETE / NOOP
      ↓
[7] пишем в SQLite, эмбеддим новый текст, апсертим в Qdrant
```

Шаги 2–7 — фоновая задача. Агент не ждёт судью.

**Gate (шаг 2)** — главный рычаг стоимости. Судья зовётся когда:
- закрылась сессия, **или**
- накопилось 10 сообщений с прошлого вызова, **или**
- в сообщении явное «запомни / remember» → зовём немедленно

Детали и цифры — в `04-judge.md`.

## Путь чтения

```
запрос агента: {query, owner_id, agent_id, budget_tokens}
      ↓
эмбеддим query (локально, ~30 мс)
      ↓
Qdrant: top-50 с фильтрами по owner/scope/status
      ↓
пересчёт score: similarity + importance + свежесть
      ↓
дедуп почти-одинаковых
      ↓
набиваем до budget_tokens
      ↓
возвращаем 10–30 фактов
```

Судья в пути чтения **не участвует**. Чтение — это чистый поиск, оно должно
быть быстрым и бесплатным. Детали формулы — в `05-retrieval.md`.

## Ночной консолидатор

Раз в сутки, отдельным процессом, через Batch API (в два раза дешевле):

- склеить почти-дубли (similarity > 0.92 внутри одного owner+type)
- сжать длинные цепочки апдейтов в один факт
- пометить `status='expired'` то, у чего вышел `valid_until`
- понизить importance у фактов, которые ни разу не попали в выдачу за 90 дней

Ничего не удаляем физически. Только меняем `status`.

## Границы: что сюда НЕ кладём

| Не кладём | Куда вместо этого |
|---|---|
| Документацию, статьи, книги | отдельная RAG-коллекция в том же Qdrant |
| Кодовую базу | индексируется отдельно, у неё другой цикл жизни |
| План текущей задачи | состояние агента, живёт часы |
| Историю переписки целиком | она в SQLite, но в поиск не идёт |

Причина одна: если положить сюда документацию React, то на запрос
«какой у меня любимый язык» поиск будет пробиваться сквозь 50 000 чанков доков.

Общее правило: **сюда идёт то, что стоит помнить про пользователя и его мир.
Не то, что можно найти.**
