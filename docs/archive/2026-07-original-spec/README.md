# Memory Service — проектная документация

Единый сервис памяти для всех твоих агентов. Локальные эмбеддинги, судья по API.

## Что это

Отдельный HTTP-сервис. Агенты не лезут в базу напрямую — только через API.
Один экземпляр обслуживает чат-ассистента, кодового агента, ресерч-агента и т.д.

## Железо и бюджет

| Что | Где | Почему |
|---|---|---|
| BGE-M3 (эмбеддинги) | локально, MPS | вызывается на каждом сообщении и каждом поиске |
| Qdrant | локально, Docker | векторный индекс |
| SQLite | локально, файл | источник правды |
| Judge (Haiku 4.5) | Claude API | вызывается редко, нужен язык и строгий JSON |

Целевой бюджет: **$5–10/месяц**. Расчёт и способы удержаться — в `04-judge.md`.

Ограничение: MacBook Pro M1 Pro, 16 GB. Локальную LLM не запускаем.

## Три правила, которые нельзя нарушать

1. **SQLite — источник правды. Qdrant — производный индекс.**
   Qdrant должен восстанавливаться из SQLite одной командой. Это даёт право
   безнаказанно менять модель эмбеддингов и промпты.

2. **Сырые сообщения не удаляются никогда.**
   Промпт экстрактора ты перепишешь раз десять. Каждый раз надо иметь
   возможность прогнать всю историю заново.

3. **`owner_id` есть везде с первого дня.**
   Пользователь пока один. Добавить поле позже — миграция данных и правка
   всех запросов.

4. **Факт не может происходить только из слов ассистента.**
   Иначе система начинает подтверждать собственные галлюцинации, и найти
   начало контура будет невозможно. Проверка на уровне записи, не в промпте.

5. **Всё, что произошло, попадает в `events`.**
   Журнал append-only: создание, правки, смена типа, удаление, выдачи, отказы
   судьи. Это материал, на котором ты через год будешь улучшать систему.
